# 使用手册

技能：**卖点提炼**（`sellingpoint-extract`）　·　L1 原子技能　·　v1.0.0

---

## 一、环境要求

| 项 | 要求 |
|---|---|
| Agent 平台 | WorkBuddy / ChatGPT / DeepSeek Harness / Kimi Work / 豆包工作中任一 |
| Python | 3.8+（**仅当本技能自带脚本时需要**；纯对话使用不需要） |
| 第三方依赖 | 无。脚本只使用标准库 |
| 网络 | 无强制要求；Excel/图片类处理在本地完成 |

## 二、安装

### 2.1 目录放置（推荐）

```bash
cp -r sellingpoint-extract ~/.workbuddy/skills/          # WorkBuddy / 通用
```

### 2.2 各平台差异

| 平台 | 方式 | 注意事项 |
|---|---|---|
| WorkBuddy | 放到 `~/.workbuddy/skills/` | 支持自动触发，也可显式点名 |
| ChatGPT | 上传 zip | 需账号支持 Skills |
| DeepSeek Harness | `新建技能 安装:<repo-url>` | 需要仓库可访问 |
| Kimi Work | 上传 zip / 放目录 | **不会自动调用**，必须显式点名技能 |
| 豆包工作 | `新建技能 安装:<repo-url>` | 触发词识别依赖 description 质量 |

### 2.3 安装后自检

```bash
# 在技能库根目录执行（技能目录内没有 tools/）
python3 tests/run.py
```

校验项：目录名与 `name` 一致、只使用标准字段、正文不含平台专有工具名、触发词中英双语且信息量足够。**任一项不通过，技能在部分平台会静默不加载。**

## 三、快速上手

### 3.1 纯对话方式（零安装）

```text
用 sellingpoint-extract 技能：<把你的材料贴进来>
```

### 3.2 脚本方式（推荐，结果可复现）

```bash
python3 scripts/sellingpoint_extract.py --file examples/input/product.json
```

### 3.3 工作流调用方式

把脚本当作一个纯函数使用：stdin/文件进，stdout/文件出，退出码表达判定结果。因此可以直接嵌进任何编排器（Agent、CI、定时任务）。

## 四、参数总表

### 4.1 输入字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 商品资料（参数 / 描述） | ✅ | 缺失会导致早退或输出不可用 |
| 目标人群 | ⬜ | 提升质量，缺失不阻塞 |
| 竞品对照 | ⬜ | 提升质量，缺失不阻塞 |
| 买家评论 | ⬜ | 提升质量，缺失不阻塞 |

### 4.2 触发词

| 语言 | 触发词 |
|---|---|
| 中文 | 卖点提炼、提炼卖点、商品卖点、卖点卡 |
| 英文 | selling point extraction、value props |

### 4.3 脚本参数

```bash
python3 scripts/sellingpoint_extract.py --help
```

参数细节以 `scripts/sellingpoint_extract.py` 的 `--help` 输出为准。

## 五、输出物说明

**FAB 卖点卡（特性 / 优势 / 利益）**

```markdown
| 特性 | 优势 | 利益 | 证据 |
## 按人群排序
```

交付前逐条核对：

- [ ] 每条卖点有明确利益点，非纯参数复述
- [ ] 参数原值引用，未四舍五入

## 六、排错手册

按「症状 → 原因 → 处理」组织。表里的每一条都来自真实使用中撞出来的问题。

| # | 症状 | 原因 | 处理 |
|---|------|------|------|
| 1 | 已知坑（详见 SKILL.md） | 纯参数罗列不是卖点——'500ml'是特性，'装够一天水量'才是卖点 | 按上文说明调整后重跑 |
| 2 | 已知坑（详见 SKILL.md） | 卖点过多等于没有卖点，同一渠道建议主推 3 个 | 按上文说明调整后重跑 |

### 脚本退出码含义

| 退出码 | 含义 | 典型场景 |
|---|---|---|
| 0 | 通过 | 无高危命中 |
| 1 | 警告 | 命中建议修改项 |
| 2 | 阻断 | 命中高危项，**应中断发布流程** |

> 非零退出码是**设计行为**，不是脚本报错。CI 里应据此中断，而不是忽略。

## 七、耗时与成本

| 模式 | 耗时 | 成本 |
|---|---|---|
| 脚本模式 | 通常 < 0.5 秒 | 零（本地执行，不调模型） |
| 对话模式 | 取决于平台与上下文长度 | 按平台计费 |

想更快：把脚本模式作为默认路径，只把需要语境判断的环节交给模型。
